# TMarks 书签批量整理与导入

> **skill 版本:`organize-bookmarks.v1@1.4.0`(2026-09-23)**。语义级变更必须
> bump 版本号并在文末「变更记录」追加条目;交付时在整理摘要中注明所依据的
> 版本号,防止按旧语义整理后无从追溯。命名对齐后端 AI 提示词
> (`bookmark.single.v1@1.2.0`,同源同口径)。

## 你的任务

接收用户的原始书签数据（任意格式），按下方数据模型与整理规则产出**一个 JSON 文件**
（总条数超过 300 时按「大库分批」拆为多个编号文件），用户在 TMarks 扩展设置页导入它。
输出格式必须严格匹配——导入器会拒绝非法 URL、按上限截断超长字段（标题 500、
描述 1000、标签名 50）、丢弃无法识别的字段不做任何猜测；它**不执行弱名黑名单**，
弱名会原样入库，黑名单纪律由整理者自行保证。

## TMarks 数据模型（硬约束，违反即数据丢失或导入失败）

| 字段 | 类型 | 硬限制 | 说明 |
|---|---|---|---|
| `url` | string | **必须 http/https**，≤2000 字符 | 唯一必填字段；`javascript:`/`file:`/`chrome:` 等一律丢弃 |
| `title` | string | ≤500 字符 | 缺省时导入器用 URL 顶替；不要输出"无标题"之类占位 |
| `description` | string \| null | ≤1000 字符 | 没有就 `null`，不要编造 |
| `folderPath` | string[] | **1–2 级** | 第 3 级起被静默截断;一级是分组容器,书签**默认挂二级**(`["一级", "二级"]`),仅当某领域书签太少撑不起二级目录时才一级直挂 |
| `tags` | string[] | ≤32 个/条 | 名 ≤50 字符；同名大小写不敏感复用（`Linux` 与 `linux` 是同一标签） |

URL 去重键是 **规范化 URL**（大小写归一 + 去 hash + 去尾斜杠）：
`https://a.com/x/`、`https://A.com/x#frag`、`https://a.com/x` 会被识别为重复。
整理输出前必须自己先按此键去重，保留信息最全的一条。
注意 `http://a.com/x` 与 `https://a.com/x` 是**两条不同**的书签（产品的
归一化器不统一协议）——去重时不要把它们合并，也不要丢弃其中一条。

## 整理规则（与 TMarks 内建 AI 整理一致，保持同一套秩序）

### 目录：两级骨架，数量受治理

- **一级目录 6–12 个**（软上限 16），二级每父级 4–12 个。书签不足 40 条时
  目录少而宽（可少于 6）；不要为凑数造目录。
- 结构语义:一级目录是**分组容器**(管理二级目录),书签默认挂二级——
  `["开发", "Rust"]` 而非 `["开发"]`。仅当某领域书签太少(≤5 条)才一级
  直挂。**不要**深链式三层层级——模型只支持两级。
- 同名目录在不同父级下可共存，但应避免；一级目录名互不重复。

### 弱名黑名单（目录与标签各自一份，命中即被丢弃，禁止输出）

- **目录禁用**：`Other, Uncategorized, To sort, Web pages, Links, Misc,
  其他, 未分类, 待整理, 网页, 资料, 链接`
- **标签禁用**：`other, uncategorized, todo, webpage, website, page, link,
  content, info, misc, reference, collection, 其他, 未分类, 待整理, 网页,
  网站, 页面, 资料, 参考, 收藏, 链接, 内容, 信息`

  这些名字不承载信息。无法归类的书签放 `folderPath: []`（顶层未分类,
  产品有对应视图与统计）并给出具体标签，而不是塞进垃圾抽屉目录。

### 标签：具体、可复用、语言一致

- 每条 **3–5 个**；名词（`rust`、`编译器`、`色彩理论`），不用句子或形容词堆砌。
- 跨条目复用是标签系统的核心价值：先列出本次输出中出现 ≥2 次的标签清单，
  孤儿标签（全库只出现 1 次）尽量换成可复用的近义标签。
- 标签与目录分工：目录回答"在哪一类"，标签回答"关于什么"——
  `folderPath: ["开发", "Rust"]` + `tags: ["异步", "tokio", "教程"]` 而不是目录塞满语义。
- **语言跟随用户书签的主体语言**（中文库出中文目录标签，英文库出英文），
  除非单个书签明显是另一语言的资源。

### 复用用户现有库（能读到时优先做）

若可访问用户的 TMarks 数据（扩展本地库或让用户提供现有目录/标签清单）：
**优先复用已有名称**（大小写不敏感），新目录/标签只在前者覆盖不了时创建。
绝不输出与已有目录仅大小写不同的新目录。
标签库越大，复用权重越高（对齐后端 `TAG_REUSE_LIMITS`）：能读到的已有标签
≥50 个时，新建标签需确证现有候选中没有同义/近义表达；≥150 个时默认禁止
新建标签，全部从已有标签中选。

## 输出格式

单个 JSON 文件（UTF-8），顶层三种形态任选其一（推荐第一种）：

```json
{
  "bookmarks": [
    {
      "title": "Tokio 官方文档",
      "url": "https://tokio.rs/tokio/tutorial",
      "description": "Rust 异步运行时的官方教程",
      "folderPath": ["开发", "Rust"],
      "tags": ["rust", "异步", "文档"]
    },
    {
      "title": "Cloudflare Workers 文档",
      "url": "https://developers.cloudflare.com/workers/",
      "description": null,
      "folderPath": ["开发", "云平台"],
      "tags": ["cloudflare", "serverless", "文档"]
    },
    {
      "title": "色彩理论入门",
      "url": "https://example.com/color-theory",
      "folderPath": ["设计", "设计基础"],
      "tags": ["色彩", "构图"]
    }
  ]
}
```

字段名是 **camelCase**（`folderPath` 不是 `folder_path`）。不需要的字段可省略
（`description` 省略等同 null）。不要输出 id、created_at、图标等导入器不认的字段。

### 大库分批（总条数 > 300 时必读）

单个回复放不下数千条高质量整理结果，且输出越长质量越漂——分批执行：

- **先全局规划、后分批输出**：第一批之前先定稿完整目录树与标签规划（放进
  整理摘要），分批只切书签，后续批次不得推翻前面的规划。
- 每批一个独立文件（200–300 条/批，顶层仍是 `{"bookmarks": [...]}`），
  命名 `tmarks-import-01.json`、`tmarks-import-02.json`…；**批内仍完整执行
  本文件全部规则**（每批单独过一遍自检清单，去重范围仅限批内）。
- 指引用户按文件名顺序**逐个导入**，每个文件看到结果计数后再导入下一个，
  不要并行开多个导入。导入器无条数上限，入口有 50MB 文件上限——分批体量
  天然远低于它。
- 全部导入后同步自动推送（每批约 1–5 秒，服务端按 50 条/批分片陆续上传；
  在选项页「账户与同步 → 同步冲突与失败」区确认队列为空即全部上传完成）。

## 产出前自检清单（逐条过，不过不交付）

- [ ] 每条 `url` 以 `http://` 或 `https://` 开头；其余已剔除并记入报告
- [ ] 按规范化 URL 去重（大小写/hash/尾斜杠变体合并；`http://` 与 `https://` 是两条不同书签，不合并），保留最全的一条
- [ ] 所有 `folderPath` ≤2 级且书签默认挂二级;一级目录数在 6–12(书签太少则更少)
- [ ] 目录与标签零命中弱名黑名单
- [ ] 标签每条 3–5 个、≤50 字符、跨条目有复用；无单例孤儿（或已说明）
- [ ] title ≤500、description ≤1000（超长截断后语义仍完整）
- [ ] 语言与库主体一致
- [ ] 分批输出时：目录规划先于首批定稿，各批独立完整通过以上各条（去重仅限批内）

交付时给用户三样东西：**JSON 文件路径**（分批时是编号文件清单）+ **整理摘要**（几条导入、几条剔除及
原因、目录树、标签频次 Top10、**所依据的 skill 版本号**）+ **下面这段导入指引**。

## 导入步骤（转述给用户）

1. 保存 JSON 文件（如 `tmarks-import.json`）
2. 点击工具栏的 TMarks 扩展图标 → 弹窗或设置入口进入**选项页** → **数据管理**分区 → **选择导入文件**（扩展内入口无右键菜单项，勿让用户去找）
3. 选择该 JSON 文件 → 预览确认条数 → 重复策略选：
   - **跳过**（默认）：库里已有的 URL 不动
   - **合并**：已有的 URL 合并双方标签、补全缺失描述/目录
4. 导入完成后等同步（约 1–5 秒自动推送；在选项页 **账户与同步** 分区底部 **同步冲突与失败** 区确认队列为空，即已全部推送）

> 服务端同样接受逐条创建（`POST /api/v1/bookmarks`，字段 `folder_path`/`tags`），
> 但批量场景一律走文件导入——它自带去重、预览与原子执行。
